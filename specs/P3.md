# P3_SRV_API — HTTP services

**Owns (only):** `platform/server/src/services/{auth.ts, profiles.ts, saves.ts, httpApi.ts, httpApi.test.ts}`
**Contract:** docs/PLATFORM.md §4–§5 · `db.ts` Store signatures (P2 implements — TRUST them)
· `httpApi.ts` class skeleton · shared validators (`isValidToken`, `isValidSaveSlot`,
`isValidSaveData`, `isValidClaimCode`) + limits.

## Mission
REST router mounted under `/api/` (+ the `/pad` page route). Split handlers per concern:
`auth.ts` (device/claim), `profiles.ts` (me/rename/stats), `saves.ts` (slots). `httpApi.ts`
dispatches by method+path, parses JSON bodies (≤ 256KB cap), and writes JSON responses.

## Endpoints
```
POST /api/auth/device   {sig}                     → {profileId, token, name}   (201 if created)
POST /api/auth/claim    {code}                    → {profileId, token, name}   links THIS request's... 
```
— correction: claim needs BOTH the new device's intent and the code. Frozen shape:
`POST /api/auth/claim {sig, code}` → `{profileId, token}` (mints token for the linked profile;
409 unknown/expired code). `sig` validated like identity.ts SIG_MIN..SIG_MAX.
```
GET   /api/profiles/me            Bearer → {id,name,createdAt}
PATCH /api/profiles/me           Bearer {name?}        → {id,name}; name cleaned like cleanName (≤16, trim, 'Player' fallback)
GET   /api/profiles/me/stats     Bearer ?game=         → [{gameId,key,value}]
GET   /api/profiles/:id/stats    ?game=                → [{gameId,key,value}]  (public read)
GET   /api/saves/:game           Bearer                → [SaveSummary]
GET   /api/saves/:game/:slot     Bearer                → SaveRecord (data parsed JSON)
PUT   /api/saves/:game/:slot     Bearer {rev,data}     → {rev} | 409 {error:'conflict',rev} | 400 quota/slots_full as {error}
DELETE /api/saves/:game/:slot    Bearer                → 204
GET   /api/pads/:game                                  → PadLayout | 404 {error:'no_pad'}   (reads GameModule.padLayout from deps.games)
GET   /pad?game=<id>                                   → text/html via renderPadPage (import from ../padPage.js; 404 when game has no padLayout)
GET   /api/health                                      → {ok:true, degraded:<store.degraded>}
```

## Behavior
- Auth middleware: `Authorization: Bearer <token>` → `store.profileIdByToken`; else 401
  `{error:'unauthorized'}`. Only saves/me endpoints require it.
- Validation via shared validators; slot names `isValidSaveSlot`; PUT body `data` must pass
  `isValidSaveData` AND serialize ≤ SAVES.maxBytes (Buffer.byteLength of JSON.stringify).
- Errors: one envelope `{error: string}` (+ optional `rev`). Status codes: 400 bad request,
  401 unauthorized, 404 missing, 409 conflict, 413 too large. NEVER leak stack traces.
- Robustness: wrap everything; malformed JSON → 400; unknown /api/* → 404.
