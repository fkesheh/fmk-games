# P4_SRV_GATEWAY — platform server integration

**Owns (only):** `platform/server/src/{net.ts, lobby.ts, index.ts, lobby.test.ts}`
**Contract:** docs/PLATFORM.md §4.1/§4.3/§4.4 · shared protocol v2 messages (auth, pad_*)
· `services/db.ts` + `services/httpApi.ts` signatures (TRUST — P2/P3 implement).

## Mission
Wire v2 into the existing gateway without breaking any of the 7 live games or their e2e
suites. All changes ADDITIVE.

### net.ts
- `start()` gains ONE optional trailing param: `api?: (req, res) => boolean`. In the http
  handler, call it FIRST; if it returns true the request is done. Existing signature/callers stay valid.

### lobby.ts
- **Session auth:** new C2S `auth {token}` → resolve profile via store; on ok set
  `sess.profileId` and reply `{t:'auth_ok', profileId, name}`; else `{t:'auth_err', message}`.
  Sessions may also carry a profile from an HTTP-only flow — ws auth is the only path for now.
- **RoomIO implementation** gains the optional members: `profileId(id)` → sess lookup ('' when
  anonymous/unknown), `reportStats(id, delta)` → clamp via STATS limits then
  `store.addStats(profileId, gameId, delta)` inside try/catch (never throw into game threads),
  `padOwner(padSessionId)` → paired player id or null.
- **Pad pairing (platform-level):**
  - Player in a room sends `pad_pair_request` → mint 6-char code (`isValidPairCode`),
    TTL PADS.pairTtlMs, single-use; reply `{t:'pad_pair', room, token: code,
    urlPath:'/pad/?game=<gameId>'}`.
  - A NEW session kind 'pad': `join_as_pad {room, token}` → validate code+room+free slot →
    bind padSession→(room, playerSession); send `{t:'pad_joined'}` to pad and
    `{t:'pad_status', bound:true}` to player; on pad disconnect/player leave/unbind →
    `pad_status bound:false`. Invalid → `{t:'pad_rejected', reason}`.
  - Pad sessions are NOT room players: they don't appear in RoomInfo counts and get no seat.
    Their ONLY routed message is `pad_input`, which is forwarded RAW into
    `GameRoomHandle.handleMessage(padSessionId, msg)` + acked `{t:'pad_input_echo', seq}`;
    enforce ≤ PADS.inputMaxHz per pad (silently drop excess).
  - Pad sessions must survive the stale-sweep differently: pads never send game inputs;
    exempt them from stalePlayers kicking (they're not players at all).
- Lobby-level parse: route the four new C2S tags BEFORE the room-passthrough default.

### index.ts
- Create `Store` (path: `path.join(__dirname-ish, 'platform.db')`, env `PLATFORM_DB` overrides,
  `PLATFORM_DB=:memory:` forces memory) → log `[server] db degraded (in-memory)` when true.
- Create `HttpApi({store, games: GAMES})`; pass `(req,res)=>api.handle(req,res)` into
  `net.start(...)` as the api hook. Keep everything else identical.
